# P-15 Noise floor of the front end

## Goal

Find the output noise density of the front end at f_osc and the smallest sensor amplitude the lock-in resolves.

## Method

**No settling window.** The analysis is an AC sweep and a noise sweep, so no time window applies. Each noise table is one frequency. Densities are the PSpice values in V^2/Hz. Their square roots give V/sqrt(Hz).

**Reading the noise.** The noise tables give the total output density `TOTAL OUTPUT NOISE VOLTAGE` at V(VSAMPLE), the transfer `V(VSAMPLE)/V_SIN`, and the input-referred density. The `.out` values have four significant digits. Each density therefore has a rounding error of up to 0.05 %. The fold factor depends mostly on the 517 Hz term, so its error is below 0.05 %.

**Density between grid points.** P15b has no grid point at 517 Hz or at the harmonics. The densities at these frequencies are log-log interpolated on the 201-point grid. Two checks were made. First, the CSDF magnitude of V(VSAMPLE) agrees with the `.out` transfer to 4.9e-4 relative. This is the four-digit rounding of the `.out`. Second, a three-point log-log quadratic through 501.2, 524.8 and 549.5 Hz gives the density at 517 Hz to 0.003 %. Linear interpolation gives 0.36 % low, so the quadratic is used as the check. The P15a exact values are used at 517 Hz.

**Fold-down factor.** A +1/-1 square-wave demodulator folds the noise at each odd harmonic n f_osc to DC with weight w_n = (4/(n pi))^2 / 2. The DC-band density at VX is then the square root of the sum of w_n S(n f_osc). The factor is the square root of sum of w_n S(n f_osc)/S(f_osc), with n f_osc up to 100 kHz (n up to 193). Numerator and denominator both come from P15b, so the interpolation error cancels. The sum of the weights up to n = 193 is 0.997911. The weight above 100 kHz is 0.002089. The upper bound, with S above 100 kHz set equal to S(100 kHz), changes the factor by 2e-6.

**Minimum amplitude for SNR = 1.** The DC output of the demodulator for a sensor sine of amplitude A is (2/pi) G A, with G = 11.07 V/V. The DC-band noise density is fold x e_out. Its RMS value over the filter is fold x e_out x sqrt(ENBW). ENBW = 1/(4 tau) for a one-pole RC. SNR = 1 means the DC signal equals one RMS noise. This gives A_min = (pi/2) x fold x e_out x sqrt(ENBW) / G. Two bandwidths are used. tau = 0.1 s (design RC, ENBW 2.5 Hz) and tau = 10 ms (the fast RC of the run, ENBW 25 Hz).

**Demodulator noise (not simulated).** The noise analysis cannot include the demodulator, because the switches change state. The demodulator noise uses datasheet values for the OPAx192 and the 10 kOhm resistors. The values are estimates.

**R_R16 check.** The 4kTR value of a 5 kOhm resistor at 300.15 K is computed. Its noise transfer to V(VSAMPLE) is the ratio of its output noise to its 4kTR value. The input-referred value is its output noise divided by the signal gain G.

## Discussion

**Fold-down.** The fold factor is 0.9014, which agrees with the 0.90 of the index. The 517 Hz term holds 0.8106 of the 0.8126 power sum. The n = 3 term adds 0.0018. The harmonics above 7 add 0.0001. The index's 0.90 is therefore a good estimate. The exact value is 0.16 % higher. The factor is near 0.9 because the band-pass gain falls by a factor of 8 at 3 f_osc, from 11.05 V/V to 1.39 V/V. Without the band-pass the factor would be 1.

**The R_R16 share.** The 5 kOhm gain resistor makes 42.6 % of the output noise power. The simulation puts its input-referred noise at 8.28 nV/sqrt(Hz). This is 0.909 times its own 4kTR value of 9.10 nV/sqrt(Hz). So the transfer is close to 1:1, but 9 % low. The model does not give a reason. One possibility is that the INA828 model feeds RG noise into its feedback network with a different transfer from the signal. This is not verified. The INA828 datasheet input voltage noise (7 nV/sqrt(Hz) typical, as stated in the request) is not in the project, so the comparison is not verified. The datasheet value may or may not include the RG noise. The simulated input-referred value of the listed INA828 items is 5.90 nV/sqrt(Hz). The total input-referred density is 12.68 nV/sqrt(Hz).

**Lower gain resistor.** A lower RG gives a higher gain. The RG noise, 4kT R_G, falls with R_G. The later stages also fall, because their output noise is referred to the input with a larger G. The estimate in the table gives 6.5 nV/sqrt(Hz) at RG = 500 Ohm, G = 101 V/V, against 12.7 nV/sqrt(Hz) now. The estimate treats the INA828 internal term as independent of gain, and this is an assumption. A run with RG = 500 Ohm would test it. This run was not made. Because the output swing rises about nine-fold, the headroom must be checked too. The design margin is 0.2 V (`simulations/design-context.md`, section 7).

**Detection limit.** For the design RC the front end resolves about 28 nV of sensor amplitude at SNR = 1. For the fast RC it resolves about 90 nV. Both numbers exclude the sensor noise, which is TBD, and the interference, which is TBD. The resolution target is also TBD (`simulations/design-context.md`, section 5). The limit must be set before these numbers can be judged.

**Demodulator.** The estimate puts the demodulator at 2.6 % of the DC noise power, with the output resistor R3 and the op amp as the largest parts. It is an estimate only. The OPAx192 model file does not state its noise (`vendor/README.md`), so the 4.5 nV/sqrt(Hz) value is not checked against the model.

## Open points

1. The INA828 datasheet is not in the project. The "7 nV/sqrt(Hz) typical" value is not verified. The INA828 model is in the PSpice library path and was not read. The user should check whether the datasheet figure includes the RG noise.
2. The 9 % transfer deficit of R_R16 (0.909) has no explanation. Its cause is not verified.
3. The lower-RG trend is an estimate. A run at RG = 500 Ohm with the same `.NOISE` setup would test it. The headroom at G = 101 V/V is not checked.
4. The OPAx192 noise value of 4.5 nV/sqrt(Hz) is recalled and not verified. The demodulator noise is not simulated.
5. The sensor noise (`simulations/design-context.md`, section 4, TBD) and the interference (section 3, TBD) are not in the model. The A_min values are for the front end only.
6. The resolution target (`simulations/design-context.md`, section 5, TBD) decides whether 28 nV or 90 nV is acceptable. This is a requirement question for the user.
7. The entry's fold check uses the 0.90 of the index. The exact value 0.9014 differs by 0.16 %. The index may be updated by the user if it wants the exact value.
8. The design RC (tau = 0.1 s) was not run. The runs used cout = 1 uF. A_min at tau = 0.1 s is computed from the formula with the 517 Hz density and the P15b fold. This is not checked by a run with cout = 10 uF.

## Judge note (27 October 2026)

The judge checked the datasheet values on the TI product pages (ti.com/product/INA828 and ti.com/product/OPA192, read 27 October 2026). The INA828 input voltage noise is 7 nV/sqrt(Hz) typical at 1 kHz. Its input common-mode headroom is 2 V to each supply, which matches the P-09 clamp. The OPA192 input voltage noise is 5.5 nV/sqrt(Hz) at 1 kHz, not the 4.5 nV/sqrt(Hz) used above. With 5.5 nV/sqrt(Hz) the op amp part of the demodulator estimate grows by (5.5/4.5)^2 = 1.49 times. The demodulator share stays a few percent of the DC noise power, and A_min changes by less than 1 %. The INA828 output noise term (e_NO) is not on the product page and was not checked.

The simulated input-referred noise (12.7 nV/sqrt(Hz)) exceeds the INA828 input noise of 7 nV/sqrt(Hz), because the 5 kOhm gain resistor alone adds 9.1 nV/sqrt(Hz) at G = 11 V/V. A higher in-amp gain (smaller RG) is the main lever for a lower noise floor, within the headroom limits of P-09.
