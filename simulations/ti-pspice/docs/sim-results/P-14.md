# P-14 Filter tolerance Monte Carlo

## Goal

Find the spread of the front-end phase and gain at f_osc for given component tolerances, and compare the error of reading X alone with the error of reading R (D-08).

## Method

**Sample set.** Section 0 of the CSDF is the Monte Carlo NOMINAL run. Sections 1 to 499 are Pass 2 to Pass 500. The `.out` file lists 499 passes. So the random sample count is 499, not 500. Each section holds one AC point at 517 Hz.

**Columns.** The CSDF has two columns, and both hold the same complex value, `V(VSAMPLE)`. The check `column 0 == column 1` is true for all 500 sections. The probes `VP` and `VM` therefore appear only as the complex voltage. The script takes `H = V(VSAMPLE)` as the complex value. The `.out` file gives the phase of `VP(VSAMPLE)` in degrees. The script compares its own phase deviations with the `SORTED DEVIATIONS` table of the `.out` file. All 499 passes match. The largest difference is 9.2e-7 deg. So the unit is degrees, and the sign convention agrees.

**Settling.** Not applicable. The run is a single-frequency AC analysis with no transient window. The check of the statistics is a convergence test. The phase mean and std are computed on the first 100, 200, 300 and 499 samples (Table 4).

**Primary definition (the entry's).** The X reading is taken with the phase calibrated at the nominal circuit. The per-sample phase deviation from nominal stays in the reading. With `r = H / H0`, where `H0` is the nominal complex value:

| Quantity | Definition |
|---|---|
| Phase deviation | `ph = angle(r)` (deg) |
| Gain, R | `g = abs(r)`, error `R = g - 1` (%) |
| Gain, X alone | `X = g cos(ph)`, error `X = g cos(ph) - 1` (%) |
| Extra error of X over R | `extra = X - g = g (cos(ph) - 1)` (%) |

**Secondary definition (uncalibrated).** The total phase `phi = angle(H)` includes the nominal phase of about +1.5 deg to +1.6 deg. The reading `Re(H) / abs(H_nom) - 1` and `Re(H) / abs(H) - 1 = cos(phi) - 1` are shown as a second reading. This reading is not calibrated. It is not the entry's quantity, and it is given for comparison only.

**Statistics.** The standard deviation uses `ddof = 1`. The `.out` file uses `ddof = 0`, and this is checked below. The standard errors come from a bootstrap of the 499 PSpice samples with 2000 resamples. The standard error of the mean is `std / sqrt(n)`, and the standard error of the std is `std / sqrt(2 n)` for a normal sample.

**numpy reference.** The script draws 200 000 samples with seed 2026. Each resistor (RG = R16, R17, R18, R21, R22) is uniform within plus or minus 1 %. Each capacitor (C1 = C_C1, C2 = C_C2, C3 = C_C3, C4 = C_C4) is uniform within plus or minus 5 %. The ideal chain follows `ti-pspice-PSpiceFiles/differential-amplifier/README.md` section 3:

- `G = 1 + 50 kOhm / RG` (section 3.1).
- `H_HP(s) = s^2 R17 R18 C1 C2 / (s^2 R17 R18 C1 C2 + s R17 (C1 + C2) + 1)` (section 3.2).
- `H_LP(s) = 1 / (s^2 R22 R21 C4 C3 + s C3 (R22 + R21) + 1)` (section 3.3).
- `H = G x H_HP x H_LP`.

The README high-pass formula matches a direct nodal solution of the same stage. The maximum relative difference is 2.3e-16. The numpy reference uses the entry's definition, so the numpy values can be compared with the entry values directly.

**Pass bands.**

- Phase std from 3.1 deg to 3.6 deg, as the entry states.
- Gain std: the entry gives no band. The analyst uses about 3 % relative around 3.59 %, which gives 3.48 % to 3.70 %. This band is an analyst interpretation.
- Extra X rows: the entry value plus or minus two standard errors from the 499 PSpice samples. The bands are given in Table 3.

**Tolerance check.** The `.out` file lists no sampled device values. It lists only the nominal bias point, the device model parameters and the sorted output deviations. The check that every sampled R and C lies within 1 % and 5 % is not verified.

## Discussion

**Phase and gain spread.** The phase std of 3.44 deg lies inside the 3.1 deg to 3.6 deg band. It is 2.3 % above the numpy value of 3.37 deg. The relative standard error of a std from 499 samples is about 1 / sqrt(2 x 498) = 3.2 %, so the difference is within sampling error. The gain std of R (3.62 %) differs from numpy (3.59 %) by 0.7 %. Both are inside the analyst band.

**Nominal offset.** The PSpice nominal magnitude is 0.055 % below the ideal value. The phase is 0.11 deg below the ideal value. P-09 found the same offset with its own method, namely -0.055 % and -0.126 deg. P-09 attributes this to the amplifier models. The INA828 phase at 517 Hz is -0.06 deg in P-09. The rest of the offset is not verified. This run uses a direct AC analysis, so the phase is not affected by the fit. The offset moves all samples by the same small amount and does not change the spreads in Table 2.

**Extra X error (entry definition).** The PSpice extra error has a mean of -0.180 %, a std of 0.246 % and a 2.5 % point of -0.884 %. The numpy reference with the same definition gives -0.172 %, 0.225 % and -0.819 %. The entry values are -0.17 %, 0.23 % and -0.82 %. All three PSpice values lie inside the sampling bands of Table 3. The extra term is about minus sigma_phi^2 / 2 in radians. With sigma_phi = 3.36 deg, this is -0.1725 %, which matches the entry. The extra term scales with the phase variance. The ratio (3.44 / 3.36)^2 = 1.05 explains about half of the ratio 0.246 / 0.225 = 1.09 between the PSpice and numpy stds. The rest is sampling.

**X alone.** The PSpice mean of X is -0.196 %. The numpy mean is -0.302 %, which equals the entry value. The PSpice mean lies 0.6 standard errors of X from the entry value, so the difference is within sampling.

**Only the extra X error is removed by R.** The gain spread of about 3.6 % acts on R and X in the same way. It appears in both readings with a correlation of 0.996. Computing R removes only the cos(ph) term of the phase deviation. For a phase spread of 3.4 deg, that term is about 0.2 % on average and about 0.9 % in the lower tail. The spread of the gain itself stays in R and in X alike.

**Uncalibrated reading.** The secondary reading in Table 5 uses the total phase. Its extra error is about 0.04 % more negative than Table 2, because the nominal phase of about 1.5 deg adds to each sample. This reading does not match the entry definition, so it is not used for the pass or fail verdict.

**Relation to the design limit.** The Draft limit in `simulations/design-context.md` section 7 is 1 deg of phase, or 0.1 % of the output. The phase std of 3.44 deg is more than three times that limit. About 76 % of the PSpice samples have a phase deviation larger than 1 deg in absolute value. This is a design issue for the reviewer, not a simulation fail. See Open points.

## Open points

1. **Nominal values.** The entry expects 11.079 V/V and +1.63 deg. The direct AC run gives 11.0732 V/V and +1.518 deg. The difference is the same as in P-09. The cause is not verified. A model test of the INA828 and OPAx192 phase at 517 Hz would settle it.
2. **Tolerances in the design context.** `simulations/design-context.md` has no front-end tolerance. Section 6 lists only the demodulator resistor tolerance as TBD. The entry says that the tolerances are TBD in section 6. This is only partly right. The 1 % and 5 % values are Draft test values in the circuit.
3. **Phase limit.** The phase std of 3.44 deg is far above the Draft review limit of 1 deg (`simulations/design-context.md` section 7). The phase accuracy in section 5 is TBD. About 76 % of PSpice samples exceed 1 deg. The design reviewer should decide on the severity.
4. **Sampled device values.** The `.out` file does not list the sampled R and C values. So the check that the sampled deviations stay within 1 % and 5 % is not verified. A run that prints the device values would check it. Not verified whether PSpice supports such a probe in this `.MC` form.
5. **Sample count.** The entry says 500 runs. The run gives 499 random samples plus the nominal section. The entry wording should say 499 samples. Not changed.
6. **Probe names.** The entry says the probes are VP and VM. The CSDF stores the complex `V(VSAMPLE)` twice. The phase and magnitude come from the complex value. The script derives both. The `.out` table confirms the degree unit of the phase.
7. **Command record.** The `.json` does not record the command. The `.cir` header still names `P14_mc`. The reconstructed command is recorded above. Not verified.
8. **Runtime.** The run took 1638 s. This is longer than the default 600 s runner timeout. The quirk is recorded in `docs/simulation-quirks.md`.
